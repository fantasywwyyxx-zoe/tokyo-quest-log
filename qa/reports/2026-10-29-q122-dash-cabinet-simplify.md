# Q-122 DASH RUN 框体精简：与主人公场景双马路同屏，读起来乱（S2，设计）

**证据**：Zoe 实机截图（2026-10-29 11:30，构建 5f3c5bd）红圈两处——上圈主人公场景（道路＋心愿旗＋勇者），下圈 Dash 框体的实况预览窗（又是道路＋障碍＋勇者）。原话：「他们同时出现有点乱，dash run能更精简一点么？」

## 病灶
框体预览窗与正上方的主人公场景是**同一母题的两次全幅呈现**（路、勇者、纵深），上下叠放必然打架。这与她上一条令（"看不懂是小游戏"）不矛盾：要"一眼是游戏"，不等于要"再画一整条马路"。

## 方向（QA 建议，开发部可另案但须满足验收）
- 预览窗**撤除或大幅缩小**（如只留一条窄带/图标化路况条）；框体收成紧凑一条：RUN 标＋标题＋目标/ベスト＋START；
- 识别性靠标题、目标胶囊（300m=券）与柠檬 START 承担，不靠第二幅场景画；
- 主人公场景（含远景心愿旗构图）零改动、零遮挡。

## 附带观察（中间车道读感）
同批 Zoe 问「中间的马路不让走？」。静态核查：三车道同权，勇者出生在中道，障碍可落中道（框体预览自己就摆了一只在中道），碰撞按车道序号判定——**中道不是禁区**。但游戏画面里中道的纵深带明显比两侧亮，容易读成"中央分隔带/不是路"。建议绘制时三道明度拉平，或车道虚线把中道轮廓点明。此项为观察，是否改由开发部/Zoe 定。

## QA 复测口径
- 主人公页 844/600 首屏：Dash 区高度较现版显著收窄（实测对比），页面一屏读完不拥挤；
- 仍可一眼识别为可玩小游戏（标题/目标/START 三件在）；
- START 于 390×600 仍在首屏内（现版实测 y354–394、滚动深度 0，不许倒退）。
