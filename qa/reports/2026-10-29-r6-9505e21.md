# QA Round 6 · 登录版 9505e21（TQL v2026.10.28-auth）· 2026-10-29

方法说明（先行）：QA 沙盒的 headless Chrome 无代理出网（curl 可达、浏览器 fetch 全灭），故真实 OTP 链按开发部交接的口径分两层验：**UI/客户端逻辑用 CDP Fetch 打桩**（真 SDK 从 CDN 下载后本地回放、/auth/v1/otp 与 /verify 按拟真响应打桩、预检按 CORS 规范应答），**端点真实性**用开发部今晚直连 200＋Zoe 本人已收到验证码邮件的既有证据。r6d 首跑因打桩漏了预检应答导致发送假失败——那是 QA 测试台的问题、非产品缺陷，已修正重跑（r6e）为准。

## 通过项
- **三入口同窗**：标题右下「LOG IN／ログイン」（旁带游客说明行）、设置 ACCOUNT 区「ログイン」、主人公页账号行「アカウント：ゲスト（タップでログイン）」——三处打开同一个登录窗（主步：邮箱/Google/游客三键＋旧地址导入链接「旧アドレスのセーブデータを取り込む」在位）。
- **Google**：点击出「準備中」系文案（EN: "Google sign-in is still being prepared — please use email for now."／JA 同义），不崩不跳。待 provider 开通后按开发部通知补验真实跳转。
- **邮箱步**：格式错误即时内联报错（EN "Enter a valid email address."／JA 同义），不发请求。
- **发送→验证码步**：发送真实 POST /auth/v1/otp（打桩计数=1，预检 1 次）；验证码步 **6 格**齐全，到达文案「qa@example.com にコードを送りました（有効期限60分）」。
- **错误文案分型**：错码按服务端 error_code 分型——不一致「コードが一致しません。メールを確認してもう一度どうぞ。」／过期（otp_expired）「コードの有効期限が切れています。再送して新しいコードでお試しください。」均不出窗、不崩。
- **60 秒重发冷却**：发送后重发键 disabled，提示「再送できるまで N 秒」每 5 秒实测 55→50→45→40 递减；约 60 秒后解禁，提示切换「届かないときは再送できます。」。
- **重发确实重发**：点击再送后 /auth/v1/otp POST 计数 1→2，提示重置 55 秒、到达文案重显。审计曾报「重发按钮不重发」经 UI 层实测**不成立**，本项关闭（与开发部源码复核结论一致）。
- **设置账户区**：游客状态行「ゲスト — 記録はこの端末に保存されます」、ログイン/ログアウト键位、未同期标记位在位；版本戳行 #buildVerLine = **TQL v2026.10.28-auth** 实测渲染。
- **更新横幅（Q-106③ 机制）**：源码核实——仅 https＋非 localhost 时 fetch(location.pathname, no-store) 比对 TQL_BUILD，不同才揭 #verBanner（JA 文案「新しいバージョンがあります — タップで再読み込み」、点按 reload、✕ 关闭、离线 catch 静默）。本地环境被其自身守卫排除、无法运行时触发，属设计如此；下个构建上线时可在真域名上事后验。
- **应援窗三语**：JA/EN/ZH 全文与 Zoe 定稿口径一致（正式上线准备中／应援是动力／将来与城市活动店铺联动为大家争取福利／量力而行），Ko-fi 键 href = https://ko-fi.com/tokyoquestlog。
- **游客回归**：旧档（Lv1 种子）正常载入；新档创建→开始→欢迎券 ×1 扭蛋实抽（券 1→0、OWNED 0→1、新品 NEW!＋即穿键、零券文案「NO TICKETS — EARN EXP!」）；一览/DAILY/地图导航切换正常。
- **断网降级**：SDK 不可达时静默游客模式（源码 catch 注记＋实测）——主动发送时只给一行「通信が不安定です。少し待ってもう一度どうぞ。」（EN: "Network hiccup — try again in a moment."），不刷屏、游戏全程可玩。
