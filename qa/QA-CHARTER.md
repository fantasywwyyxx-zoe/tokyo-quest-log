# QA部 · 部章（2026-10-28 Zoe 下令成立）

## 使命
渲染级视觉检测：把游戏真的跑起来、截下来、逐屏挑错。专攻 Zoe 点名的四类：
1. **显示/UI 问题**：溢出、截断、词中折行、重叠、胶囊/徽标断裂、关闭按钮半重叠、夜间对比残留。
2. **抠图不全**：图片裁切残缺、边缘缺口、透明边/描边断裂、精灵缺件（如没脖子那类）。
3. **挤占屏幕空间**：元素占位过大、单按钮独占整排、一屏放不下要滚动、留白失衡（该满的不满、该空的不空）。
4. **基础可用性冒烟**：页面可达、按钮可点、状态切换（三语/昼夜）不炸版。

## 检测矩阵（每轮必测）
- 手机：390×844（主）、390×667（Zoe 实机短屏，适配基准）
- 电脑：1440×900
- 状态：新档（标题→建角）与老档（地图/列表/详情/每日/记录/设置）各一轮路径

## 方法
- 工具：chrome-headless-shell 截图（已实证可用，2026-10-28）+ 后续 CDP 驱动做页面导航与元素量测（工具任务 Q-001）。
- 每条问题必须带：截图证据 + 视口 + 页面/状态 + 复现条件 + 严重度（S1 挡路 / S2 难看 / S3 瑕疵）。
- 动画中间帧不算数：问题要在稳定态复现才立案。
- QA 只检测与验收，不直接改游戏代码：修复进开发部/Codex 调试部的队列，修完 QA 复测销项。
- 与调试部（Codex）的分工：Codex = 静态代码/逻辑排查（T8）；QA部 = 渲染画面验收。两者清单在 HANDOFF 汇总，避免重复立案。

## 运转
- 低打扰：每轮报告落仓库 qa/reports/，汇总进待批清单，不单独打扰 Zoe；S1 问题即时上报主聊天。
- Zoe 的实机仍是最终法庭：QA 结论与实机冲突时，以实机为准并回溯检测方法。
